# 용어 작성 가이드

## 파일

| 파일 | 내용 |
|---|---|
| `src/content/terms/<id>.json` | 용어 1개. 파일 이름이 id이고 URL이 된다 (`/terms/wrc-plus/`, 영어는 `/en/terms/wrc-plus/`). 언어와 상관없는 값과 한국어 글. |
| `src/content/en/terms/<id>.json` | 같은 용어의 영어 글. 아래 ‘영어 파일’. |
| `src/content/stubs.json` | 준비 중 용어 목록. |
| `src/content/ladders.json` | 사다리 목록(화면 이름 ‘주제’). 적힌 순서대로 홈과 주제 페이지에 나온다. 이름은 한국어(`name`)와 영어(`en`) 둘 다 쓴다. |

스키마는 `src/lib/schema.ts`에 zod로 정의돼 있다. 이 문서와 스키마가 다르면 둘 다 고친다.

## 스키마 (`src/content/terms/<id>.json`)

| 필드 | 필수 | 내용 |
|---|---|---|
| (파일 이름) | 예 | id. kebab-case (`wrc-plus.json`, `attack-angle.json`). 파일 안에는 `id`를 쓰지 않는다. |
| `abbr` | 예 | 영어 화면의 표제어와 목록 이름. 영문 약어나 이름 (`wRC+`, `Attack Angle`). 한국어 화면에서는 칩이 한글이고 `abbr`가 약어(AVG, FPCT)일 때만 표제어 아래에 작게 보인다. |
| `chip` | 예 | 한국어 화면의 목록과 표제어에 쓰는 이름. 팬이 실제로 부르는 말로, 한국어가 더 익숙하면 한국어 (`타율`, `배럴`, `블라스트`). 영어 화면은 `abbr`를 쓴다. |
| `ko` | 예 | 한국어 이름. 칩과 같으면(타율) 목록에서 따로 적지 않고, 칩으로 시작하면(어택 앵글 (배트 진입각)) 나머지만 적는다. |
| `aliases` | 아니오 | 검색용 별칭. 한글 발음, 붙여쓰기, 관련 하위 지표 이름. 검색은 두 언어의 이름과 별칭을 모두 본다. |
| `level` | 예 | 1 기본, 2 중급, 3 심화. |
| `order` | 예 | 같은 레벨 안에서의 순서. 작을수록 앞이다. 전체 용어 목록과 홈 입구에 이 순서로 나온다. 10 단위로 매겨 사이에 끼워 넣을 자리를 둔다. |
| `cats` | 예 | `타격`, `투구`, `수비`, `종합`, `트래킹` 중 하나 이상. |
| `added` | 아니오 | 처음 공개된 해. 값이 있으면 용어 머리줄에 ‘N년 도입’이 붙고 홈의 ‘심화 지표’에 먼저 나온다. 최근(2024년 이후) 지표에만 쓴다. |
| `summary` | 예 | 한 문장 정의. 용어 페이지 리드와 검색에 쓰인다. |
| `easy` | 예 | 문단 1~3개. 화면 이름은 ‘쉬운 설명’. 수식 없이 장면과 예로 쓴다. |
| `scale` | 아니오 | 수치 기준(눈금). 아래 별도 설명. |
| `formula` | 아니오 | `expr`(식)과 `vars`(`[기호, 설명]` 목록). |
| `deep` | 예 | 문단 1~4개. 화면 이름은 ‘자세한 설명’. 원리, 계산 세부, 한계, 다음 단계 지표. |
| `myth` | 아니오 | `claim`(흔한 오해)과 `truth`(실제로는). 실제로 자주 보이는 오해가 있을 때만 쓴다. |
| `leagues` | 아니오 | `[{lg, t}]`. KBO·NPB와 실제로 다른 점이 있을 때만 쓴다. |
| `related` | 예 | 같이 볼 용어 id. 작성된 용어만 넣는다. |
| `sources` | 예 | `[{t, u}]`. 원 출처 링크 1개 이상. |

`stubs.json`의 항목은 사다리에만 점선으로 보이는 준비 중 용어다 (`id`, `chip`, `en`(영어 화면 이름), 선택 `added`). 작성하면 `stubs.json`에서 빼고 `terms/<id>.json`을 만든다.

`ladders.json`의 항목은 `name`, `en`, `hint`, `steps`(왼쪽이 기본, 오른쪽이 심화)로 이뤄진다. 한 용어가 여러 사다리에 들어가도 된다. `name`은 화면에 그대로 나오는 주제 이름이다(‘투수 평가’, ‘구위 분석’처럼 무엇을 다루는지만). `hint`는 지금 화면에 쓰지 않는다.

### `scale`

- `min`, `max`: 막대의 양 끝.
- `dir`: `high`(클수록 좋음), `low`(작을수록 좋음), `none`(좋고 나쁨이 아님).
- `fmt`: `int`, `dec1`, `dec2`, `dec3`. `dec3`은 1 미만이면 앞의 0을 뺀다 (.316).
- `unit`: 선택. `%`, `°`, ` in`. 다른 단위가 필요하면 `src/lib/schema.ts`의 `UNITS`에 먼저 넣는다.
- `avg`: 선택. `{v, t}`. 출처가 있는 리그 평균이거나 정의상 평균(100, 0)일 때만 넣는다.
- `marks`: `[{v, t}]` 구간 눈금. 라벨이 겹치지 않게 범위의 10% 이상 간격을 둔다.
- `band`: 선택. `[a, b]` 강조 구간 (예: 어택 앵글 이상적 범위).
- `note`: 선택. 기준(한 시즌, 포지션, 구종)과 ‘대략적인 구간’이라는 점을 밝힌다.

## 영어 파일 (`src/content/en/terms/<id>.json`)

2026-10-27에 영어판을 만들었다. 용어마다 영어 파일이 있어야 한다. 숫자와 출처 URL은 한국어 파일의 것을 그대로 쓰고, 영어 파일에는 글만 둔다.

| 필드 | 필수 | 내용 |
|---|---|---|
| `name` | 예 | 영어 정식 이름. `abbr`와 같으면 목록에서 따로 적지 않는다. |
| `aliases` | 아니오 | 검색용 영어 별칭. |
| `summary`, `easy`, `deep` | 예 | 한국어 파일과 같은 역할, 같은 문단 수 제한. |
| `scale` | 한국어에 있을 때 | `avg`(글), `marks`(`[{v, t}]`, `v`는 한국어 파일과 같은 숫자), `note`. 한국어에 있는 것만 쓴다. |
| `formula` | 한국어에 있을 때 | `expr`, `vars`. 식에 한글이 있으면 영어로 바꿔 쓴다. |
| `myth`, `leagues` | 한국어에 있을 때 | 한국어 파일과 개수가 같다. |
| `sources` | 예 | 한국어 파일과 같은 URL을 같은 순서로. 제목의 한국어 부분만 영어로 바꾼다. |

쓰는 법:

- 한국어 글을 옮기되 글자대로 번역하지 않는다. 같은 사실, 같은 예, 같은 숫자를 자연스러운 미국 영어로 다시 쓴다. 한국 독자에게만 필요한 문장(방어율 같은 옛 이름, km/h 환산 설명)은 뺀다.
- 한국어 파일에 없는 숫자, 날짜, 사실은 더하지 않는다. 외부 글(FanGraphs, MLB.com, Baseball Savant)의 문장은 영어여도 옮기지 않는다.
- 평균 설명(`scale.avg`)에는 화면이 크게 적는 숫자를 같은 표기로 넣는다(`2026 MLB average 4.17 (2025: 4.15)`). 화면은 그 숫자를 빼고 옆에 적는다.
- 피할 것: 지표를 사람처럼 쓰기(‘WAR tells us’), 꾸민 비유, 문단 끝마다 정리하는 문장, ‘remember’ 같은 훈계, 줄표(—) 남발, 용어마다 되풀이되는 문장.

## 빌드 때 검사

`npm run build`(`astro build`)는 아래 중 하나라도 어긋나면 실패하고, 어느 파일의 어느 필드인지 알려 준다. `npm test`는 빌드 없이 같은 검사를 돌린다.

- 위 스키마: 필수 필드, 허용 값, 문단 수, 출처 URL 형식. 스키마에 없는 필드(오타)도 막는다.
- `scale`: `min` < `max`, `marks`·`avg`·`band`가 `min`~`max` 안, `marks` 사이 간격이 범위의 10% 이상.
- `related`: 작성된 용어 id만. 자기 자신, 중복, 준비 중 용어는 안 된다.
- `ladders.json`의 `steps`: 용어나 준비 중 용어 id만. 한 사다리 안에서 중복은 안 된다.
- `stubs.json`: id 중복, 이미 작성된 용어와 같은 id, 어느 사다리에도 없는 항목은 안 된다.
- 파일 이름(id)은 kebab-case.
- 영어 파일: 용어마다 하나씩 있고, 눈금 숫자·출처 URL·있고 없는 부분(눈금, 수식, 오해, 리그)이 한국어 파일과 같고, 한글이 남아 있지 않다. 평균 설명에 한국어처럼 평균 숫자가 들어 있다.
- `ladders.json`, `stubs.json`의 영어 이름(`en`)에 한글이 없다.

## 쓰는 법

2026-10-27에 다시 정했다. 앞서 ‘사람 문체’의 표시(장면으로 시작하기, 짧게 끊는 문장, 구어 맺음, 문단 수 다르게 하기)를 목록으로 적었더니, 그 표시가 모든 용어에 고르게 들어가서 오히려 새 틀이 됐다. 그래서 표시 목록과 예문을 빼고 태도만 적는다.

- 기록을 잘 아는 팬이 친구에게 용어 하나를 설명한다고 생각하고 쓴다. 설명이 끝나면 멈춘다. 장면으로 시작하기, 짧은 문장으로 끊기, 다음 지표로 넘기는 마무리 같은 건 어느 것도 꼭 넣지 않는다.
- **summary**: 한 문장. 처음 보는 사람이 읽고 무엇을 재는 숫자인지 알 수 있어야 한다. 화면에서 제목 바로 아래에 크게 나온다.
- **easy**: 처음 보는 사람 기준이다. summary를 다시 말하지 않는다. 다른 용어를 쓰면 그 자리에서 풀어 쓴다.
- **deep**: 이미 아는 사람 기준이다. 계산 세부, 언제 틀리는지, 산출처별 차이를 쓴다.
- **myth**: 실제로 자주 보이는 오해가 있을 때만 쓴다. ‘무조건’, ‘항상’을 붙여 일부러 틀린 말을 만들지 않는다. 오해를 그대로 적고, 답은 ‘맞는 말이다. 하지만’ 같은 틀 없이 바로 쓴다.
- **leagues**: 리그 상수·가중치가 따로 계산되는 경우처럼 그 용어에만 해당하는 차이를 쓴다. 다른 용어에 적은 문장을 되풀이하지 않는다.
- 문체는 한다체다. 영문 약어는 처음 나올 때 한국어로 풀어 준다.
- 중계와 팬이 실제로 쓰는 말을 쓴다(방어율, 텍사스 안타, 워닝 트랙). 영문 지표에 한국어 이름을 새로 지어 붙이지 않는다.
- 본문에서 화면을 가리키지 않는다(‘사다리의 다음 칸’, ‘아래 표’). 다음 지표로 가는 길은 사다리와 같이 보기가 맡는다.
- 피할 버릇:
  - 지표를 사람처럼 쓰기(‘지표가 말하는’), 꾸민 비유, 문단 끝마다 정리하는 문장, ‘기억해 두자’ 같은 훈계.
  - 같은 맺음(‘~를 본다’, ‘~하는 이유다’, ‘의심해 볼 만하다’)이나 같은 장면을 여러 용어에서 되풀이하기.
- 합치기 전에 용어 사이의 되풀이를 찾아본다. 세 용어 이상에 나오는 첫 문장, 맺음, 장면, 단서는 고치거나 뺀다.
- UI 문구는 해요체다. 화면은 이름만 붙이고 스스로를 설명하지 않는다. 설명이 필요한 버튼이면 버튼이나 이름을 바꾼다. 책을 흉내 낸 말(판, 일러두기, 뜻, 판권)과 홍보 문구는 쓰지 않는다.
- 화면의 이름은 무엇이 있는지만 말한다(‘기본 지표’, ‘주제’, ‘쉬운 설명’). 독자를 가정하는 이름(‘처음이라면’, ‘이미 안다면’)이나 설계 개념을 드러내는 비유(‘사다리’, ‘노선’, ‘역’)는 쓰지 않는다. 개념 이름은 코드와 문서에서만 쓴다.

## 저작권과 데이터

- 설명 문장은 직접 쓴다. 외부 글을 번역하거나 문장 구조를 따라 쓰지 않는다.
- 정의, 공식, 리그 평균 같은 사실은 쓰되 원 출처를 링크한다.
- 실제 선수 기록과 이름을 예시로 쓰지 않는다. 예시는 가상 수치로 쓴다.
- 확인하지 못한 수치는 쓰지 않는다. 확인한 값은 `docs/verified-facts.md`에 날짜와 함께 추가한다.

## 준비 중 용어 (stubs)

2026-10-15에 처음 준비 중이던 12개(타율, ERA, xFIP, SIERA, 타구 속도, 하드히트%, 구속, 회전수, K%, 수비율, 배트 스피드, 스윙 타이밍)를 모두 작성해 `stubs.json`은 비어 있다.

- 새 용어를 사다리에 먼저 걸어 두려면 `stubs.json`에 `{ "id", "chip", "en", "added"(선택) }`로 넣는다. 사다리에 점선 칸으로 보이고, 홈 ‘심화 지표’에도 `added`가 있으면 ‘준비 중’으로 나온다.
- 2026-10-23에 원문과 대조해 ERA·xFIP에는 `scale`을 붙였다(FIP도 같은 방식으로 바꿨다). 구간을 어떻게 정했는지는 `docs/verified-facts.md`의 ‘FanGraphs Library 경험칙 표’에 있다. 경험칙 표의 ‘평균’이 실제 리그 평균과 다르면 표를 그대로 옮기지 말고, 리그 평균을 기준으로 환산하거나 `scale`을 붙이지 않는다.
